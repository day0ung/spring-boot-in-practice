# 3.5 템플릿과 콜백

## 템플릿/콜백 패턴이란?

- 전략 패턴의 컨텍스트를 **템플릿**, 익명 내부 클래스로 만들어지는 오브젝트를 **콜백**이라고 부름
- 스프링에서는 이 방식을 **템플릿/콜백 패턴**이라고 특별히 명명

| 용어 | 역할 |
|---|---|
| 템플릿 | 변하지 않는 작업 흐름을 담은 코드 (`JdbcContext`) |
| 콜백 | 템플릿 안에서 호출되는 특정 로직 (`StatementStrategy` 익명 클래스) |

## 템플릿/콜백의 동작 원리

### 특징

- 콜백은 보통 **단일 메서드 인터페이스**를 사용 (전략 패턴은 여러 메서드도 가능)
- 콜백 인터페이스의 메서드는 템플릿의 작업 흐름 중 특정 시점에 호출됨
- 콜백은 자신을 생성한 클라이언트의 변수를 직접 참조 가능 (클로저)

### 동작 흐름

```
클라이언트                  템플릿                    콜백
    │                         │                        │
    │  콜백 오브젝트 생성        │                        │
    │──────────────────────────────────────────────────▶│
    │                         │                        │
    │  템플릿 메서드 호출(콜백 전달)                       │
    │────────────────────────▶│                        │
    │                         │  콜백 메서드 호출         │
    │                         │───────────────────────▶│
    │                         │  콜백 결과 반환           │
    │                         │◀───────────────────────│
    │  최종 결과 반환            │                        │
    │◀────────────────────────│                        │
```

### JdbcContext에 적용된 템플릿/콜백

```java
// 콜백 인터페이스
public interface StatementStrategy {
    PreparedStatement makePreparedStatement(Connection c) throws SQLException;
}

// 템플릿
public void workWithStatementStrategy(StatementStrategy stmt) throws SQLException {
    // ... try/catch/finally (변하지 않는 흐름)
    ps = stmt.makePreparedStatement(c); // 콜백 호출
    // ...
}

// 클라이언트 + 콜백 생성
public void deleteAll() throws SQLException {
    workWithStatementStrategy(c -> c.prepareStatement("delete from users")); // 콜백
}
```

## 편리한 콜백의 재활용

### 콜백의 분리와 재활용

- 단순 SQL만 다른 경우 콜백 코드에 중복이 생김
- SQL 문자열만 받아서 콜백을 생성하는 메서드로 분리

```java
public void executeSql(final String query) throws SQLException {
    workWithStatementStrategy(c -> c.prepareStatement(query));
}
```

```java
public void deleteAll() throws SQLException {
    executeSql("delete from users"); // 훨씬 간결
}
```

### 콜백과 템플릿의 결합

- `executeSql()`은 `UserDao`만 사용하는 게 아니므로 `JdbcContext`로 이동

```java
public class JdbcContext {
    public void executeSql(final String query) throws SQLException {
        workWithStatementStrategy(c -> c.prepareStatement(query));
    }
}
```

```java
// UserDao
public void deleteAll() throws SQLException {
    this.jdbcContext.executeSql("delete from users");
}
```

## 템플릿/콜백의 응용

### 제네릭스를 이용한 콜백 인터페이스

- 콜백 메서드가 값을 반환해야 하는 경우 제네릭 활용

```java
public interface ResultSetExtractor<T> {
    T extractData(ResultSet rs) throws SQLException;
}
```

```java
public <T> T queryWithResultSetExtractor(String sql, ResultSetExtractor<T> rse)
        throws SQLException {
    Connection c = dataSource.getConnection();
    PreparedStatement ps = c.prepareStatement(sql);
    ResultSet rs = ps.executeQuery();
    T result = rse.extractData(rs); // 콜백 호출
    // close ...
    return result;
}
```

```java
// 사용 예: getCount()
public int getCount() throws SQLException {
    return jdbcContext.queryWithResultSetExtractor(
        "select count(*) from users",
        rs -> {
            rs.next();
            return rs.getInt(1);
        }
    );
}
```

## 스프링의 JdbcTemplate

- 스프링은 이미 JDBC 코드에 사용할 수 있는 완성된 템플릿/콜백을 `JdbcTemplate`으로 제공
- 직접 만든 `JdbcContext`와 유사하지만 훨씬 다양한 기능 제공

```java
public class UserDao {
    private JdbcTemplate jdbcTemplate;

    public void setDataSource(DataSource dataSource) {
        this.jdbcTemplate = new JdbcTemplate(dataSource);
    }

    public void deleteAll() {
        jdbcTemplate.update("delete from users");
    }

    public int getCount() {
        return jdbcTemplate.queryForObject("select count(*) from users", Integer.class);
    }
}
```

## 정리

> 템플릿/콜백 패턴은 전략 패턴과 익명 내부 클래스를 조합한 것으로,  
> 변하지 않는 흐름(템플릿)과 변하는 로직(콜백)을 깔끔하게 분리한다.  
> 스프링의 `JdbcTemplate`이 이 패턴의 대표적인 구현체다.
