# 1.5 스프링의 IoC

## 오브젝트 팩토리를 이용한 스프링 IoC

### 애플리케이션 컨텍스트와 설정정보

- 스프링에서는 IoC를 담당하는 컨테이너를 **빈 팩토리(BeanFactory)** 또는 **애플리케이션 컨텍스트(ApplicationContext)** 라고 부름
- 스프링이 제어권을 가지고 직접 만들고 관계를 부여하는 오브젝트를 **빈(Bean)** 이라고 함
- 스프링 빈은 스프링 컨테이너가 생성, 관계 설정, 사용 등을 제어해주는 IoC가 적용된 오브젝트

### DaoFactory를 스프링의 설정정보로 활용

- `@Configuration`: 스프링이 빈 팩토리를 위한 오브젝트 설정을 담당하는 클래스임을 명시
- `@Bean`: 오브젝트를 만들어주는 메서드임을 명시

```java
@Configuration
public class DaoFactory {

    @Bean
    public UserDao userDao() {
        return new UserDao(connectionMaker());
    }

    @Bean
    public ConnectionMaker connectionMaker() {
        return new DConnectionMaker();
    }
}
```

- `ApplicationContext`를 이용해 `DaoFactory` 설정정보를 읽어들이고 `UserDao` 빈을 가져옴

```java
ApplicationContext context =
    new AnnotationConfigApplicationContext(DaoFactory.class);

UserDao dao = context.getBean("userDao", UserDao.class);
```

## 애플리케이션 컨텍스트의 동작 방식

- `DaoFactory`: 직접 오브젝트를 생성하고 관계를 맺어주는 코드가 있는 구체적인 팩토리
- `ApplicationContext`: 애플리케이션에서 IoC를 적용해 관리할 모든 오브젝트에 대한 생성과 관계 설정을 담당

**애플리케이션 컨텍스트 사용의 장점**

| 장점 | 설명 |
|---|---|
| 클라이언트와 구체적인 팩토리 분리 | 클라이언트는 팩토리 클래스를 직접 알 필요 없이 컨텍스트만 사용 |
| 종합 IoC 서비스 제공 | 오브젝트 생성 방식, 시점, 전략 설정, 자동생성, 후처리 등 다양한 기능 제공 |
| 빈 검색 다양화 | 이름, 타입, 어노테이션 등 다양한 방법으로 빈 검색 가능 |

## 스프링 IoC 용어 정리

- **빈(Bean)**: 스프링이 IoC 방식으로 관리하는 오브젝트. 스프링이 직접 생성과 제어를 담당
- **빈 팩토리(BeanFactory)**: IoC를 담당하는 핵심 컨테이너. 빈 등록, 생성, 조회, 반환 등 관리
- **애플리케이션 컨텍스트(ApplicationContext)**: 빈 팩토리를 확장한 IoC 컨테이너. 빈 팩토리의 기능 + 스프링이 제공하는 부가 서비스
- **설정정보(Configuration metadata)**: 애플리케이션 컨텍스트가 IoC를 적용하기 위해 사용하는 메타 정보 (`@Configuration`)
- **IoC 컨테이너**: IoC 방식으로 빈을 관리한다는 의미로 ApplicationContext를 지칭
- **스프링 프레임워크**: IoC 컨테이너, 애플리케이션 컨텍스트를 포함해 스프링이 제공하는 모든 기능을 통칭

## 정리

> `DaoFactory` 같은 순수 자바 팩토리 클래스에 `@Configuration`, `@Bean`을 붙이는 것만으로  
> 스프링의 IoC 컨테이너가 해당 설정을 읽어 빈을 관리하게 된다.
