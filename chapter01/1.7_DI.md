# 1.7 의존관계 주입(DI, Dependency Injection)

## IoC와 의존관계 주입

- IoC는 매우 느슨하게 정의된 개념으로, 스프링이 제공하는 IoC 방식을 명확히 표현하기 위해
  **의존관계 주입(Dependency Injection)** 이라는 용어를 사용
- 스프링 IoC 기능의 대표적인 동작 원리가 DI이므로 **스프링 = DI 컨테이너** 라고도 불림

## 의존관계

- A가 B에 의존한다 = B가 변하면 A에 영향을 미친다
- 의존관계에는 **방향성**이 있음 → A → B (A는 B에 의존, B는 A에 의존하지 않음)

```
UserDao ──depends on──▶ ConnectionMaker (interface)
                               ▲
                        DConnectionMaker
```

- `UserDao`는 `ConnectionMaker` **인터페이스**에만 의존
- 구체 클래스(`DConnectionMaker`)가 바뀌어도 `UserDao`에는 영향 없음 → **낮은 결합도**

## 런타임 의존관계 설정

- **설계 시점의 의존관계**: 인터페이스(`ConnectionMaker`)에만 의존, 구체 클래스 모름
- **런타임 의존관계**: 실제 실행 시점에 구체 오브젝트(`DConnectionMaker`)가 연결됨

**의존관계 주입의 3가지 조건**
1. 인터페이스에만 의존하는 코드 작성 (구체 클래스를 알지 못함)
2. 런타임 시점의 의존관계는 컨테이너/팩토리가 결정
3. 사용할 오브젝트의 레퍼런스를 외부에서 주입해줌

## UserDao의 의존관계 주입

- 기존: `UserDao`가 직접 `DConnectionMaker`를 생성 → 런타임 의존관계가 코드에 고정됨
- 개선: `DaoFactory`(스프링 컨테이너)가 런타임 의존관계를 결정하고 주입

```java
// 생성자를 통한 의존관계 주입
public class UserDao {
    private ConnectionMaker connectionMaker;

    public UserDao(ConnectionMaker connectionMaker) {
        this.connectionMaker = connectionMaker;
    }
}
```

```java
// DaoFactory가 의존관계를 결정하고 주입
@Bean
public UserDao userDao() {
    return new UserDao(connectionMaker()); // DI
}
```

## 의존관계 검색과 주입

- **의존관계 검색(Dependency Lookup)**: 오브젝트가 스스로 컨테이너에게 의존 오브젝트를 요청

```java
// 의존관계 검색 방식
public UserDao() {
    ApplicationContext context = new AnnotationConfigApplicationContext(DaoFactory.class);
    this.connectionMaker = context.getBean("connectionMaker", ConnectionMaker.class);
}
```

| 구분 | 의존관계 주입(DI) | 의존관계 검색(DL) |
|---|---|---|
| 방식 | 컨테이너가 주입 | 오브젝트가 직접 검색 |
| 스프링 API 의존 | 없음 | 있음 (`ApplicationContext` 사용) |
| 권장 여부 | ✅ 권장 | 스프링 API에 의존하므로 가급적 지양 |

- 단, 애플리케이션 기동 시점(`main()`, 테스트)처럼 DI가 불가능한 경우에는 DL 사용

## 의존관계 주입의 응용

### 기능 구현의 교환

- 운영 DB → 로컬 DB로 교체 시 `DaoFactory`의 `connectionMaker()`만 수정하면 됨
- `UserDao` 코드는 전혀 변경 불필요

```java
@Bean
public ConnectionMaker connectionMaker() {
    // return new ProductionDBConnectionMaker(); // 운영
    return new LocalDBConnectionMaker(); // 로컬 개발
}
```

### 부가기능 추가

- `UserDao`를 수정하지 않고 DB 연결 횟수를 카운팅하는 기능을 추가할 수 있음

```java
public class CountingConnectionMaker implements ConnectionMaker {
    int counter = 0;
    private ConnectionMaker realConnectionMaker;

    public CountingConnectionMaker(ConnectionMaker realConnectionMaker) {
        this.realConnectionMaker = realConnectionMaker;
    }

    public Connection makeConnection() throws ... {
        this.counter++;
        return realConnectionMaker.makeConnection();
    }
}
```

## 메서드를 이용한 의존관계 주입

### 수정자 메서드(Setter) 주입

```java
public class UserDao {
    private ConnectionMaker connectionMaker;

    public void setConnectionMaker(ConnectionMaker connectionMaker) {
        this.connectionMaker = connectionMaker;
    }
}
```

```java
@Bean
public UserDao userDao() {
    UserDao userDao = new UserDao();
    userDao.setConnectionMaker(connectionMaker());
    return userDao;
}
```

### 일반 메서드를 이용한 주입

- 여러 파라미터를 한 번에 받을 수 있어 수정자보다 유연하지만, 관례상 수정자 주입이 더 일반적

## 정리

> DI는 오브젝트 레퍼런스를 외부로부터 주입받고, 이를 통해 다른 오브젝트와 동적으로  
> 의존관계를 맺는다. 스프링은 DI 컨테이너로서 이 과정을 자동으로 처리해준다.
