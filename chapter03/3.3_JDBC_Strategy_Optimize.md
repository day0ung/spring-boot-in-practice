# 3.3 JDBC 전략 패턴의 최적화

## 전략 클래스의 추가 정보

- `deleteAll()`은 전략 클래스에 전달할 부가 정보가 없었지만
- `add()`는 `User` 오브젝트라는 **추가 정보**가 필요

### add() 메서드에 전략 패턴 적용

```java
public class AddStatement implements StatementStrategy {
    private User user;

    public AddStatement(User user) {
        this.user = user; // 생성자로 부가 정보 전달
    }

    public PreparedStatement makePreparedStatement(Connection c) throws SQLException {
        PreparedStatement ps = c.prepareStatement(
            "insert into users(id, name, password) values(?, ?, ?)");
        ps.setString(1, user.getId());
        ps.setString(2, user.getName());
        ps.setString(3, user.getPassword());
        return ps;
    }
}
```

```java
public void add(User user) throws SQLException {
    StatementStrategy st = new AddStatement(user); // 부가 정보를 생성자로 전달
    jdbcContextWithStatementStrategy(st);
}
```

- 전략 클래스 생성자에 필요한 정보를 주입하면 다양한 상황에 유연하게 대응 가능

## 전략과 클라이언트의 동거

### 문제점

- 메서드마다 새로운 전략 클래스(`DeleteAllStatement`, `AddStatement` 등)를 만들어야 함
- 클래스 파일이 급격히 늘어나고, `User` 같은 부가 정보를 생성자로 매번 전달해야 하는 번거로움

### 로컬 클래스

- 전략 클래스를 클라이언트 메서드 내부의 **로컬 클래스**로 선언

```java
public void add(final User user) throws SQLException {
    class AddStatement implements StatementStrategy {
        public PreparedStatement makePreparedStatement(Connection c) throws SQLException {
            PreparedStatement ps = c.prepareStatement(
                "insert into users(id, name, password) values(?, ?, ?)");
            ps.setString(1, user.getId()); // 외부 메서드의 변수 직접 접근 가능
            ps.setString(2, user.getName());
            ps.setString(3, user.getPassword());
            return ps;
        }
    }
    jdbcContextWithStatementStrategy(new AddStatement());
}
```

- 로컬 클래스는 자신이 선언된 곳의 정보에 **직접 접근** 가능 → 생성자로 전달할 필요 없음
- 클래스 파일이 분리되지 않아 관리가 편함

### 익명 내부 클래스

- 이름조차 필요 없는 **익명 내부 클래스**로 더 간결하게 표현

```java
public void add(final User user) throws SQLException {
    jdbcContextWithStatementStrategy(new StatementStrategy() {
        public PreparedStatement makePreparedStatement(Connection c) throws SQLException {
            PreparedStatement ps = c.prepareStatement(
                "insert into users(id, name, password) values(?, ?, ?)");
            ps.setString(1, user.getId());
            ps.setString(2, user.getName());
            ps.setString(3, user.getPassword());
            return ps;
        }
    });
}
```

```java
public void deleteAll() throws SQLException {
    jdbcContextWithStatementStrategy(new StatementStrategy() {
        public PreparedStatement makePreparedStatement(Connection c) throws SQLException {
            return c.prepareStatement("delete from users");
        }
    });
}
```

- 익명 내부 클래스는 선언과 동시에 오브젝트를 생성
- 단 한 번만 사용될 클래스에 적합

## 전략 패턴 최적화 비교

| 방식 | 장점 | 단점 |
|---|---|---|
| 독립 전략 클래스 | 재사용 가능 | 클래스 파일 증가, 부가정보 전달 번거로움 |
| 로컬 클래스 | 외부 변수 직접 접근, 클래스 파일 분리 없음 | 코드가 다소 길어짐 |
| 익명 내부 클래스 | 가장 간결, 선언과 생성 동시에 | 재사용 불가, 복잡해지면 가독성 저하 |

## 정리

> 전략 클래스를 익명 내부 클래스로 만들면 클라이언트와 전략을 한 곳에 모을 수 있어  
> 코드가 간결해지고, 외부 변수에 직접 접근할 수 있어 부가 정보 전달도 자연스러워진다.  
> 이 구조가 스프링의 템플릿/콜백 패턴의 기반이 된다.
