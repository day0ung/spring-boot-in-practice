# 3.4 컨텍스트와 DI

## JdbcContext의 분리

- `jdbcContextWithStatementStrategy()`는 `UserDao`에만 쓰이는 게 아니라 다른 DAO에서도 사용할 수 있는 범용 코드
- 이를 별도의 클래스 `JdbcContext`로 분리

### 클래스 분리

```java
public class JdbcContext {
    private DataSource dataSource;

    public void setDataSource(DataSource dataSource) {
        this.dataSource = dataSource;
    }

    public void workWithStatementStrategy(StatementStrategy stmt) throws SQLException {
        Connection c = null;
        PreparedStatement ps = null;
        try {
            c = dataSource.getConnection();
            ps = stmt.makePreparedStatement(c);
            ps.executeUpdate();
        } catch (SQLException e) { throw e; }
        finally {
            if (ps != null) try { ps.close(); } catch (SQLException e) {}
            if (c != null) try { c.close(); } catch (SQLException e) {}
        }
    }
}
```

```java
public class UserDao {
    private JdbcContext jdbcContext;

    public void setJdbcContext(JdbcContext jdbcContext) {
        this.jdbcContext = jdbcContext;
    }

    public void deleteAll() throws SQLException {
        this.jdbcContext.workWithStatementStrategy(
            c -> c.prepareStatement("delete from users")
        );
    }
}
```

### 빈 의존관계 변경

```xml
<bean id="userDao" class="springbook.user.dao.UserDao">
    <property name="jdbcContext" ref="jdbcContext" />
</bean>

<bean id="jdbcContext" class="springbook.user.dao.JdbcContext">
    <property name="dataSource" ref="dataSource" />
</bean>

<bean id="dataSource" class="...SimpleDriverDataSource">
    ...
</bean>
```

의존관계:
```
UserDao → JdbcContext → DataSource
```

## JdbcContext의 특별한 DI

- `JdbcContext`는 인터페이스가 아닌 **구체 클래스**를 직접 DI 받음
- 일반적으로 DI는 인터페이스를 통해 해야 하지만, `JdbcContext`는 예외적으로 괜찮은 이유:
  1. `JdbcContext`는 스프링 컨테이너가 관리하는 싱글톤 빈 → 상태가 없고 서비스 오브젝트로 사용
  2. `JdbcContext`가 `DataSource`라는 DI를 필요로 함 → 스프링 빈이어야 함
  3. `UserDao`와 `JdbcContext`는 강하게 결합되어 있어 굳이 인터페이스 분리가 불필요

### 스프링 빈으로 DI

- XML 설정에서 `jdbcContext` 빈을 등록하고 `userDao`에 주입하는 방식 (위 XML 참고)
- 오브젝트 간의 실제 의존관계가 설정을 통해 드러난다는 장점

### 코드를 이용하는 수동 DI

- `JdbcContext`를 스프링 빈으로 등록하지 않고 `UserDao` 내부에서 직접 생성하여 DI

```java
public class UserDao {
    private JdbcContext jdbcContext;

    public void setDataSource(DataSource dataSource) {
        this.jdbcContext = new JdbcContext(); // 직접 생성
        this.jdbcContext.setDataSource(dataSource); // 수동 DI
    }
}
```

| 방식 | 장점 | 단점 |
|---|---|---|
| 스프링 빈으로 DI | 의존관계가 설정에 드러남 | 구체 클래스를 빈으로 노출 |
| 수동 DI | 외부에 드러나지 않음 | 싱글톤이 아님, `JdbcContext`의 DI를 직접 처리 |

## 정리

> `JdbcContext`처럼 인터페이스 없이 구체 클래스를 DI 받는 것은 특별한 경우이며,  
> 스프링 빈으로 등록하는 방식과 수동 DI 방식 중 상황에 맞게 선택할 수 있다.
