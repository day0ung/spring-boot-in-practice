# 6.6 트랜잭션 속성

## 트랜잭션 정의

- `DefaultTransactionDefinition`이 구현하는 `TransactionDefinition` 인터페이스가 트랜잭션 동작 방식을 결정

### 트랜잭션 전파 (Propagation)

- 이미 진행 중인 트랜잭션이 있을 때 새 트랜잭션을 어떻게 처리할지 결정

| 전파 속성 | 설명 |
|---|---|
| `REQUIRED` | 기본값. 진행 중인 트랜잭션 있으면 참여, 없으면 새로 시작 |
| `REQUIRES_NEW` | 항상 새 트랜잭션 시작. 기존 트랜잭션은 보류 |
| `NOT_SUPPORTED` | 트랜잭션 없이 실행. 기존 트랜잭션은 보류 |
| `MANDATORY` | 반드시 기존 트랜잭션 있어야 함. 없으면 예외 |
| `NEVER` | 트랜잭션 없이만 실행. 기존 트랜잭션 있으면 예외 |
| `SUPPORTS` | 있으면 참여, 없으면 트랜잭션 없이 실행 |
| `NESTED` | 중첩 트랜잭션 생성 |

```java
// A 트랜잭션 시작
A.work() {
    B.work(); // REQUIRED: A 트랜잭션 참여
    C.work(); // REQUIRES_NEW: 별도 트랜잭션 시작
}
// A 트랜잭션 커밋
```

### 격리 수준 (Isolation)

- 동시에 여러 트랜잭션이 진행될 때 데이터 접근 규칙

| 격리 수준 | 설명 |
|---|---|
| `DEFAULT` | DB 드라이버 기본값 |
| `READ_UNCOMMITTED` | 커밋 안 된 데이터도 읽기 가능 (더티 리드 발생) |
| `READ_COMMITTED` | 커밋된 데이터만 읽기 가능 |
| `REPEATABLE_READ` | 한 트랜잭션 내에서 같은 데이터를 읽으면 항상 동일한 결과 |
| `SERIALIZABLE` | 완벽한 격리. 성능 저하 가능 |

### 제한시간 (Timeout)

```java
definition.setTimeout(30); // 30초 이내 완료 안 되면 예외
```

### 읽기전용 (Read Only)

```java
definition.setReadOnly(true); // 쓰기 작업 시 예외 또는 무시
```

### 롤백/커밋 규칙

- 기본: `RuntimeException` → 롤백, `CheckedException` → 커밋
- 커스텀 롤백 규칙 설정 가능

## 트랜잭션 인터셉터와 트랜잭션 속성

- `TransactionInterceptor`를 사용해 메서드별로 트랜잭션 속성 설정 가능

```xml
<bean id="transactionAdvice"
      class="org.springframework.transaction.interceptor.TransactionInterceptor">
    <property name="transactionManager" ref="transactionManager" />
    <property name="transactionAttributes">
        <props>
            <prop key="get*">PROPAGATION_REQUIRED,readOnly,timeout_30</prop>
            <prop key="upgrade*">PROPAGATION_REQUIRED</prop>
            <prop key="*">PROPAGATION_REQUIRED</prop>
        </props>
    </property>
</bean>
```

### 트랜잭션 속성 문자열 형식

```
PROPAGATION_[전파속성], ISOLATION_[격리수준], timeout_[초], readOnly, -[롤백예외], +[커밋예외]
```

```
PROPAGATION_REQUIRED                   // 기본 전파
PROPAGATION_REQUIRED,readOnly          // 읽기 전용
PROPAGATION_REQUIRED,readOnly,timeout_30  // 30초 타임아웃
PROPAGATION_REQUIRED,-MyException      // MyException 발생 시 롤백
```

## 포인트컷과 트랜잭션 속성의 적용 전략

1. **트랜잭션 포인트컷 표현식은 타입 패턴 또는 빈 이름 사용**
   - `execution(* *..*Service.*(..))`: Service로 끝나는 모든 타입의 메서드
   - `bean(*Service)`: 빈 이름이 Service로 끝나는 빈의 모든 메서드

2. **공통 메서드 이름 규칙으로 트랜잭션 속성 일관성 유지**
   - `get*`, `find*`, `search*` → readOnly
   - `add*`, `update*`, `delete*` → 쓰기 트랜잭션

3. **읽기 전용 트랜잭션으로 성능 최적화**
   - 불필요한 DB 쓰기 방지, 일부 DB에서 성능 향상

## 정리

> 트랜잭션 속성(전파, 격리 수준, 읽기 전용, 타임아웃)을 메서드 이름 패턴별로 설정하면  
> 세밀한 트랜잭션 제어와 성능 최적화를 동시에 달성할 수 있다.
