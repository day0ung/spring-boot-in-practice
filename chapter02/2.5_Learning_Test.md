# 2.5 학습 테스트로 배우는 스프링

## 학습 테스트란?

- 자신이 만든 코드가 아닌 **다른 사람이 만든 프레임워크나 라이브러리를 테스트**하는 것
- 테스트 목적: 기능 검증이 아닌 **API나 프레임워크의 동작 방식을 학습**하고 이해하는 것

## 학습 테스트의 장점

| 장점 | 설명 |
|---|---|
| 다양한 조건 검증 | 다양한 조건하에서 API를 실행해보고 결과를 확인 |
| 학습 효과 향상 | 테스트를 직접 작성하면서 기능을 체계적으로 학습 |
| 레퍼런스 역할 | 작성된 학습 테스트는 이후 기능을 사용하는 예제 코드로 활용 가능 |
| 변화 감지 | 라이브러리 버전 업그레이드 시 동작 변화를 테스트로 빠르게 감지 |
| 개발 문서 보완 | API 문서보다 더 직관적이고 실행 가능한 문서 역할 |

## JUnit 테스트 오브젝트 테스트

- JUnit이 테스트마다 새 인스턴스를 만드는지 직접 확인하는 학습 테스트

```java
public class JUnitTest {
    static JUnitTest testObject;

    @Test
    public void test1() {
        assertThat(this, is(not(sameInstance(testObject))));
        testObject = this;
    }

    @Test
    public void test2() {
        assertThat(this, is(not(sameInstance(testObject))));
        testObject = this;
    }

    @Test
    public void test3() {
        assertThat(this, is(not(sameInstance(testObject))));
        testObject = this;
    }
}
```

- 매 테스트마다 `this`가 이전 `testObject`와 다른 인스턴스임을 확인
- JUnit의 "테스트 독립성을 위해 매번 새 인스턴스 생성" 원칙을 실제로 검증

## 스프링 테스트 컨텍스트 테스트

- 스프링이 하나의 컨텍스트를 여러 테스트에서 공유하는지 확인하는 학습 테스트

```java
@RunWith(SpringJUnit4ClassRunner.class)
@ContextConfiguration
public class JUnitTest {
    @Autowired
    ApplicationContext context;

    static Set<JUnitTest> testObjects = new HashSet<>();
    static ApplicationContext contextObject = null;

    @Test
    public void test1() {
        assertThat(testObjects, not(hasItem(this)));
        testObjects.add(this);

        assertThat(contextObject == null || contextObject == this.context, is(true));
        contextObject = this.context;
    }

    @Test
    public void test2() { /* 동일한 검증 */ }

    @Test
    public void test3() { /* 동일한 검증 */ }
}
```

- 테스트 오브젝트는 매번 다르게 생성 → `testObjects`에 현재 인스턴스가 없음
- 컨텍스트는 항상 동일한 오브젝트 → `contextObject == this.context` 항상 true

## 버그 테스트

- 코드에 버그가 발생했을 때, **버그를 재현하는 테스트를 먼저 작성**하는 방법

### 버그 테스트의 장점

| 장점 | 설명 |
|---|---|
| 버그 재현 보장 | 테스트가 실패함으로써 버그가 존재함을 명확히 증명 |
| 수정 확인 | 버그 수정 후 테스트가 통과하면 수정이 완료됐음을 보장 |
| 회귀 방지 | 이후 동일한 버그가 재발하면 테스트가 즉시 실패 → 회귀 방지 |
| 기술적 이해 향상 | 버그 원인을 파악하고 테스트로 표현하는 과정에서 깊이 있는 이해 가능 |

### 버그 테스트 작성 프로세스

```
1. 버그 발생 확인
      ↓
2. 버그를 재현하는 테스트 작성 (테스트 실패 확인)
      ↓
3. 버그 수정
      ↓
4. 테스트 통과 확인
      ↓
5. 전체 테스트 실행으로 회귀 없음 확인
```

## 동등분할과 경계값 분석

- **동등분할(Equivalence Partitioning)**: 같은 결과를 내는 입력값의 범위를 구분하고 각 범위에서 하나씩 테스트
- **경계값 분석(Boundary Value Analysis)**: 경계 근처의 값(0, -1, 1, MAX 등)을 집중적으로 테스트

```java
// 예: getCount()의 경계값 테스트
assertThat(dao.getCount(), is(0)); // 경계값: 0
dao.add(user1);
assertThat(dao.getCount(), is(1)); // 경계값: 1
```

## 정리

> 학습 테스트는 프레임워크나 라이브러리의 동작 방식을 직접 검증하며 학습하는 효율적인 방법이다.  
> 버그 테스트는 버그를 재현하고 수정을 검증하며, 이후 회귀를 방지하는 안전망 역할을 한다.
