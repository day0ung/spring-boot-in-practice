# 5.4 메일 서비스 추상화

## 메일 발송 기능 추가

- 레벨 업그레이드 시 사용자에게 메일 발송
- `JavaMailSenderImpl`을 직접 사용하면 테스트 시 실제 메일 서버가 필요해짐

```java
private void upgradeLevel(User user) {
    user.upgradeLevel();
    userDao.update(user);
    sendUpgradeMail(user);
}

private void sendUpgradeMail(User user) {
    JavaMailSenderImpl mailSender = new JavaMailSenderImpl();
    mailSender.setHost("mail.server.com");

    SimpleMailMessage mailMessage = new SimpleMailMessage();
    mailMessage.setTo(user.getEmail());
    mailMessage.setFrom("admin@example.com");
    mailMessage.setSubject("업그레이드 안내");
    mailMessage.setText("등급이 " + user.getLevel().name() + "로 업그레이드 되었습니다.");

    mailSender.send(mailMessage);
}
```

## 테스트의 문제점

- 테스트 실행 시마다 실제 메일이 발송됨
- 메일 서버가 없으면 테스트 자체가 실패
- 메일 발송은 부하가 큰 작업 → 단위 테스트에 부적합

## MailSender 인터페이스 도입

- 스프링이 제공하는 `MailSender` 인터페이스로 추상화

```java
public interface MailSender {
    void send(SimpleMailMessage simpleMessage) throws MailException;
    void send(SimpleMailMessage[] simpleMessages) throws MailException;
}
```

```java
public class UserService {
    private MailSender mailSender;

    public void setMailSender(MailSender mailSender) {
        this.mailSender = mailSender;
    }

    private void sendUpgradeMail(User user) {
        SimpleMailMessage mailMessage = new SimpleMailMessage();
        mailMessage.setTo(user.getEmail());
        mailMessage.setSubject("업그레이드 안내");
        mailMessage.setText("등급이 " + user.getLevel().name() + "로 업그레이드 되었습니다.");
        mailSender.send(mailMessage);
    }
}
```

## 테스트용 DummyMailSender

- 아무 동작도 하지 않는 테스트 대역(Test Double) 구현

```java
public class DummyMailSender implements MailSender {
    public void send(SimpleMailMessage mailMessage) throws MailException {}
    public void send(SimpleMailMessage[] mailMessages) throws MailException {}
}
```

```xml
<!-- 테스트 설정 -->
<bean id="mailSender" class="com.example.DummyMailSender" />

<!-- 운영 설정 -->
<bean id="mailSender" class="org.springframework.mail.javamail.JavaMailSenderImpl">
    <property name="host" value="mail.server.com" />
</bean>
```

## 테스트 대역 (Test Double)

| 종류 | 설명 |
|---|---|
| 테스트 스텁(Stub) | 테스트 중 호출 시 미리 정의된 값을 반환. 동작 검증 불필요 |
| 목 오브젝트(Mock) | 호출 여부, 호출 횟수, 파라미터 등을 기록하고 검증 |

### 목 오브젝트로 메일 발송 검증

```java
public class MockMailSender implements MailSender {
    private List<String> requests = new ArrayList<>();

    public List<String> getRequests() { return requests; }

    public void send(SimpleMailMessage mailMessage) throws MailException {
        requests.add(mailMessage.getTo()[0]); // 수신자 주소 기록
    }
    public void send(SimpleMailMessage[] mailMessages) throws MailException {}
}
```

```java
@Test
public void upgradeLevels() throws Exception {
    MockMailSender mockMailSender = new MockMailSender();
    userService.setMailSender(mockMailSender);

    userService.upgradeLevels();

    List<String> requests = mockMailSender.getRequests();
    assertThat(requests.size(), is(2)); // 업그레이드 대상 2명
    assertThat(requests.get(0), is(users.get(1).getEmail()));
    assertThat(requests.get(1), is(users.get(3).getEmail()));
}
```

## 정리

> 메일 서비스도 트랜잭션과 마찬가지로 인터페이스를 통해 추상화하면  
> 테스트 시 DummyMailSender나 MockMailSender로 교체할 수 있어  
> 외부 의존 없이 빠르고 안정적인 단위 테스트가 가능해진다.
