# 6.8 트랜잭션 지원 테스트

## 선언적 트랜잭션과 트랜잭션 전파

- `@Transactional`이나 AOP로 적용된 트랜잭션을 **선언적 트랜잭션**이라 함
- 트랜잭션 전파 속성 덕분에 이미 시작된 트랜잭션에 메서드들이 참여 가능

```java
// upgradeLevels() 트랜잭션 안에서 userDao.update()가 같은 트랜잭션에 참여
@Transactional
public void upgradeLevels() {
    List<User> users = userDao.getAll();
    for (User user : users) {
        if (canUpgradeLevel(user)) {
            upgradeLevel(user); // userDao.update() → 같은 트랜잭션
        }
    }
}
```

## 트랜잭션 동기화 테스트

- 같은 트랜잭션 안에서 작업이 이루어지는지 직접 확인

```java
@Test
public void transactionSync() {
    // 별도 트랜잭션으로 실행 → 각각 독립적
    userService.deleteAll();
    userService.add(users.get(0));
    userService.add(users.get(1));
}
```

```java
@Test
public void transactionSync() {
    // 하나의 트랜잭션으로 묶기
    DefaultTransactionDefinition txDefinition = new DefaultTransactionDefinition();
    TransactionStatus txStatus = transactionManager.getTransaction(txDefinition);

    userService.deleteAll();
    userService.add(users.get(0));
    userService.add(users.get(1));

    transactionManager.rollback(txStatus); // 롤백 → 모든 작업 취소
    assertThat(userDao.getCount(), is(0));
}
```

## @Transactional 테스트

- 테스트 메서드에 `@Transactional`을 붙이면 테스트 종료 후 자동 롤백
- DB에 데이터가 남지 않아 테스트 독립성 보장

```java
@Test
@Transactional
public void transactionalTest() {
    userService.add(users.get(0));
    assertThat(userDao.getCount(), is(1));
    // 테스트 종료 후 자동 롤백 → DB에 데이터 없음
}
```

### @Rollback

- 테스트의 트랜잭션 롤백 여부를 명시적으로 제어

```java
@Test
@Transactional
@Rollback(false) // 커밋 → DB에 데이터 반영
public void transactionalCommitTest() {
    userService.add(users.get(0));
}
```

### @TransactionConfiguration (구버전) / @Rollback (최신)

```java
@RunWith(SpringJUnit4ClassRunner.class)
@ContextConfiguration(locations = "/test-applicationContext.xml")
@Transactional // 클래스 레벨: 모든 테스트에 트랜잭션 적용
public class UserServiceTest {

    @Test
    public void add() { ... } // 자동 롤백

    @Test
    @Rollback(false)
    public void commitTest() { ... } // 커밋
}
```

## 테스트에서 트랜잭션 사용 시 주의사항

| 상황 | 설명 |
|---|---|
| 테스트 `@Transactional` + 서비스 `REQUIRES_NEW` | 서비스 메서드가 별도 트랜잭션으로 실행되어 테스트 롤백 미적용 |
| 트랜잭션 없는 테스트 | DB 상태가 누적되므로 `@Before`에서 데이터 정리 필요 |
| 롤백 테스트 + 이메일 발송 | 롤백되어도 이메일은 이미 발송됨 → Mock 사용 필요 |

## 스프링 테스트 트랜잭션 처리 흐름

```
@Test @Transactional
    │
    ├── TransactionStatus 시작
    │
    ├── 테스트 메서드 실행
    │       └── @Transactional 서비스 메서드 (REQUIRED → 기존 트랜잭션 참여)
    │
    └── 테스트 종료 → 롤백 (@Rollback(false)이면 커밋)
```

## 정리

> 테스트에 `@Transactional`을 적용하면 테스트 후 자동 롤백되어 DB를 깨끗하게 유지한다.  
> 트랜잭션 전파를 이해하면 여러 메서드가 하나의 트랜잭션으로 묶이는 동작을 명확히 검증할 수 있다.
